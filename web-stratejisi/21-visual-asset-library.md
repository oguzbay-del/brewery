# Demleme visual asset library and publishing rules

**Status:** Active. Nine original public SVG assets plus the homepage's inline editorial SVG are integrated. Product screenshots and photography require separate approval.

## Purpose

Use original visuals to make brewing workflows, technical concepts and data relationships easier to understand. Graphics should explain the subject, not decorate empty space or imply unbuilt functionality.

## Visual language

- Editorial and technical, with warm off-white surfaces, charcoal typography and restrained amber accents.
- Simple geometry, clear labels, generous whitespace and consistent line weights.
- Prefer custom SVG for diagrams and simple charts: responsive, lightweight, crisp at every viewport and accessible through title, description, alt text and a nearby caption.
- Use original illustrations selectively for emotional/product context; do not use generic stock imagery.
- Keep the homepage hero artwork visually unchanged unless separately approved.

## Approved visual classes

| Class | Purpose | Evidence / labelling rule |
|---|---|---|
| Workflow diagrams | Explain Home and Business journeys | Label as illustrative workflow where not a current product flow |
| Record relationship diagrams | Explain conceptual data entities | Explicitly say planned model / conceptual relationship |
| Data examples | Explain technical concepts such as gravity or target-vs-actual | Simulated values must be labelled; never present as product output or brewing advice |
| Measurement diagrams | Explain manual, instrument and connected-device source differences | Do not imply every source or integration is currently supported |
| Equipment / ingredient illustrations | Add relevant editorial context | Original assets only; no implied product functionality |
| Product screenshots | Demonstrate actual UI | Capture from approved build only; verify feature availability and redact personal/customer data |
| Photography | Add genuine brewery/homebrew context | Original or properly licensed assets only; no stock imagery without approval |

## Publication checklist

- [ ] The visual answers a specific question on the page.
- [ ] Source data is real and approved, or clearly labelled as simulated / conceptual.
- [ ] It does not imply a planned feature is available.
- [ ] SVG has an accessible title and description; the HTML image has useful alt text.
- [ ] Caption explains important caveats without relying on colour alone.
- [ ] Responsive rendering checked at desktop, tablet and narrow mobile widths.
- [ ] No customer data, unlicensed imagery, false metrics or unsupported claims.
- [ ] Asset is optimised and does not materially harm page performance.

## Density guidance

Do not put a graphic in every section. Use one meaningful visual per major concept cluster, alternating diagrams, short explanatory copy and tables. Prioritise clarity and editorial rhythm over raw image count.
